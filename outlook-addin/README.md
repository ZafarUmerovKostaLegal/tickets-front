# Kosta File — Office add-in

`https://tickets.kostalegal.com/outlook-addin/`

Панель в духе MacroView: дерево «Клиенты → Matters → папки», подсказки, куда сохранить письмо,
статус «где это письмо уже лежит», поиск по документам и вложение документов в черновик.

## Вход без отдельного окна (Nested App Auth)

Надстройка берёт токен у самого Outlook (MSAL `createNestablePublicClientApplication`), поэтому
пользователь вообще не видит отдельного входа. Нужна **одна настройка в Azure** (делает админ тенанта):

1. Entra ID → App registrations → приложение Kosta Hub → **Authentication**.
2. Платформа **Single-page application** → **Add URI**: `brk-multihub://tickets.kostalegal.com`
   (для dev ещё `brk-multihub://localhost:3001`).
3. Сохранить. У приложения уже должны быть делегированные права `User.Read` и `Mail.Read`
   (лучше сразу выдать admin consent — тогда не будет ни одного окна).

Порядок входа в панели:

1. Сохранённый токен Hub (живёт сутки) — без запросов.
2. Тихий токен от Outlook (NAA) → `POST /api/v1/auth/azure/bootstrap` → токен Hub.
3. Только если NAA недоступен (старый Outlook) или нет согласия — кнопка «Войти через Microsoft»
   (сначала окно согласия самого Outlook, затем прежний диалог входа).

При `401` от API панель сама повторяет шаг 2 и повторяет запрос.

Авторизация в итоге **та же, что у Hub** (Microsoft → токен Hub).

Два манифеста (у Microsoft нельзя смешать Mail и Word/Excel/PPT в одном `MailApp`):

| Файл | Клиенты |
|------|---------|
| `KostaFile.manifest.xml` | **Outlook Classic** (Windows), New Outlook, Outlook в браузере, Mac, Mobile |
| `KostaFile.Office.manifest.xml` | **Word**, **Excel**, **PowerPoint** (Desktop) |

Версия обоих манифестов берётся из `package.json` · Mailbox **1.5+** (новые API включаются по наличию).

## Панель «всегда как MacroView»

Web add-in не может сам открыться при старте Outlook (это умеет только VSTO/COM вроде MacroView). Ближайший эквивалент:

1. Установить манифест (лучше централизованно на тенант).
2. Открыть **Kosta File** один раз.
3. Нажать **📌** в шапке панели (New Outlook → Apps / Classic → task pane).

После закрепления панель **остаётся** при смене и закрытии письма; UI обновляется через `ItemChanged`.

## Установка Outlook (Classic / New)

1. **Get Add-ins** → **My add-ins** → **Add a custom add-in** → **Add from File…**
2. Выберите `KostaFile.manifest.xml` (**переустановите**, если стояла старая версия)
3. Откройте письмо → **Kosta File**
4. Закрепите панель **📌**
5. Вход произойдёт сам (см. выше). Кнопка «Войти через Microsoft» появится, только если тихий вход невозможен.

**Classic Windows:** после sideload перезапустите Outlook.

**Для всей фирмы (рекомендуется):** Microsoft 365 Admin → Integrated apps → Upload custom apps → тот же XML. Тогда кнопка появляется у всех без ручной установки.

## Установка Word / Excel / PowerPoint

Это **отдельный манифест** `KostaFile.Office.manifest.xml` — манифест Outlook в Word/Excel/PowerPoint не появляется.

**Для всей фирмы (рекомендуется, единственный простой способ для настольного Office):**
Microsoft 365 Admin → Settings → Integrated apps → Upload custom apps → *Office Add-in* →
`KostaFile.Office.manifest.xml` → назначить пользователям. Кнопка появится в течение нескольких часов
(иногда до суток) после перезапуска Word / Excel / PowerPoint.

**Вручную:**
- *Office в браузере:* Вставка → Надстройки → Мои надстройки → **Отправить мою надстройку** → файл манифеста.
- *Настольный Office на Windows:* в нём нет кнопки «Отправить надстройку». Положите манифест в общую
  сетевую папку, добавьте её в Файл → Параметры → Центр управления безопасностью → Каталоги доверенных
  надстроек (галочка «Показать в меню»), перезапустите Office → Вставка → Мои надстройки → **Общая папка**.

Работа: Главная → **Kosta File** → **В matter** → выберите папку в дереве → «Сохранить Word / Excel / PowerPoint».

**Требования:** Microsoft 365 / Office 2021+ (движок WebView2) или Office в браузере. Office 2016/2019 с движком
Internet Explorer надстройку не запустит — панель покажет об этом сообщение. Если панель показывает
«Kosta File не запустился», в ней будет текст ошибки — его достаточно прислать администратору.

## Что умеет панель (Outlook)

| Блок | Что делает |
|------|-----------|
| Карточка письма | «Сохранено / Не сохранено» и где именно лежит письмо (по `Message-ID`, данные с сервера — видны всем, у кого есть доступ к matter) |
| Куда обычно сохраняют | Правило → эта переписка → этот отправитель → компания отправителя (домен) → мои недавние места. Кнопка ↑ сохраняет письмо сразу |
| Папки | Клиенты → matters → папки, фильтр по названию и коду, новая папка (+), избранное (☆) |
| Перетаскивание | Письма и файлы можно бросить на папку в дереве (новый Outlook / OWA — `DragAndDropEvent`, файлы с рабочего стола — везде) |
| Поиск | Документы по названию, описанию, номеру `KL-…`; в черновике — «Вложить» и «Ссылка» |
| Избранное | Избранные matters/папки, недавние места, в черновике — недавние документы |
| Нижняя панель | Куда сохранить · письмо / вся переписка / только вложения · вложения отдельными файлами · комментарий · правило для отправителя |

Письмо сохраняется оригиналом (`getAsFileAsync`, Mailbox 1.14, с вложениями внутри) с именем
`ГГГГ-ММ-ДД Отправитель - Тема [хеш].eml`. Повторное сохранение того же письма в ту же папку
создаёт новую версию, а не дубликат. Вложения отдельными файлами — по желанию.

Сервер (`file_manager`) хранит привязки в `fm_email_filings`:
`POST /mail/lookup` — где сохранено письмо/переписка, `GET /mail/suggestions` — подсказки мест.

## Статус в Outlook

После успешной загрузки в File Manager на письмо ставится категория **Saved to Kosta**.

## Вся переписка (тред, Outlook)

В нижней панели выберите **Вся переписка** и нажмите «Сохранить»:
- первый раз — один файл `Conversation_*.eml` в выбранной папке;
- дальше в тот же matter — новая версия того же документа (check-in).

Нужно согласие **Mail.Read** (при NAA токен Graph берётся у Outlook автоматически).

## API

По умолчанию: `https://ticketsback.kostalegal.com/api/v1/files`

## Разработка

```bash
npm ci
npm run dev                # https://localhost:3001/outlook-addin/ (сертификат mkcert)
```

Sideload dev-манифестов из `manifests/dev/` — у них свои `Id` и имя «Kosta File (dev)»,
поэтому они ставятся рядом с боевой надстройкой.

| Команда | Что делает |
|---------|------------|
| `npm run build` | typecheck → проверка манифестов → `vite build` (так же в Docker и CI) |
| `npm run typecheck` | `tsc` без тестов |
| `npm test` | unit-тесты (Vitest основного проекта, `outlook-addin/src/**/*.test.ts`) |
| `npm run manifests` | пересобрать манифесты из `manifests/templates/` |
| `npm run manifests:check` | упасть, если XML в корне разошёлся с шаблонами |

### Манифесты

Правьте только `manifests/templates/*.xml` и `ENVIRONMENTS` в `scripts/manifests.mjs`,
затем `npm run manifests`. Версия — `version` в `package.json` (`0.5.0` → `0.5.0.0`).
Файлы в корне генерируются и коммитятся: их загружают админы M365.

### Безопасность

- Адрес File Manager API ограничен списком наших шлюзов (`settings.ts → ALLOWED_API_ORIGINS`):
  токен Hub никогда не уходит на чужой хост. Поле адреса доступно только в dev-сборке.
- Токен надстройки хранится в отдельном ключе `kosta.addin.hubToken` и не трогает сессию Hub SPA.
- Roaming-настройки Office ограничены ~32 КБ: туда пишется урезанная история загрузок,
  правила сохраняются всегда (`buildRoamingPayload`).
